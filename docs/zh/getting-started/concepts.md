# 核心概念

后面所有文档都会用到这里的术语。

```text
你的应用（OpenAI 或 Anthropic SDK）
   │  一个 API 密钥
   ▼
LLM Proxy
   │  模型名：具体名称        ──▶ 提供商 + 上游模型
   │  模型名：auto/fast/best  ──▶ 分类器挑选模型
   ▼
重试 · 回退 · 熔断
   │
   ▼
上游提供商 API
   │  响应翻译回客户端协议
   ▼
你的应用
```

## 协议进，协议出 {#protocol-in-protocol-out}

客户端使用两种聊天协议之一：OpenAI（`/v1/chat/completions`、`/v1/responses`，以及
embeddings、图像和音频端点）或 Anthropic（`/v1/messages`）；也可以使用 Cohere 兼容的
`/v1/rerank`。请求进入网关后先归一化成同一个内部模型。提供商序列化器把它改写成上游
要的格式，响应回来时再翻译成客户端协议。

如果上游和客户端用同一种协议，比如 Anthropic 客户端访问 Anthropic 上游，请求可以
原样转发。这就是原生透传，能保留代理归一化时会丢掉的字段。Chat Completions 不走这条
路径。

## 提供商

提供商是一个上游 API 地址和它的凭据，包括类型（OpenAI、Anthropic、Gemini、Ollama、
vLLM、SGLang、OpenRouter 等）、base URL、API 密钥、可选的自定义请求头和超时。在
[提供商](/zh/admin/providers)页面配置。影响选择顺序的是模型上的提供商映射优先级，
不是提供商记录本身的字段。

## 模型映射

模型映射给客户端可见的模型名一个提供商和一个上游模型 ID，并带上能力标记（工具、视觉、
推理等）、上下文长度和定价。路由、白名单和预算都以它为单位。名字由你决定：
`gpt-5.6-luna` 指向哪个上游都可以。

请求了没有映射的模型名，会返回 `404 model_not_found`。

## 虚拟模型

开启[智能路由](/zh/api/routing)后，会多出三个可用的模型名。

| 名称 | 用途 |
| --- | --- |
| `fast` | 最便宜且够用的模型，延迟和成本优先 |
| `auto` | 成本与质量平衡（默认倾向） |
| `best` | 质量优先，成本次要 |

分类器在进程内运行，挑出一个已映射的模型。结果同样受白名单、预算和回退规则约束。
如果开启了[路由判定器](/zh/api/routing#routing-judge)，首轮中拿不准的请求会交给一次
简短的 System One 调用裁决。

## 优先级、重试与回退

候选顺序按模型到提供商的映射优先级排列，高优先级组先试；提供商记录自己的 `priority`
字段不参与选择。同一组内由
[提供商选择策略](/zh/admin/settings#provider-selection)决定先后。

失败以后先在同一个提供商上重试（`max_retries`，默认 3 次），再回退到下一个提供商
（`max_fallback_attempts`，默认 10 次）。熔断器会跳过持续失败的提供商：默认连续 5 次
失败后冷却 60 秒。每次尝试都会写进请求日志（`fallback_attempts`、`retry_count`）。

## API 密钥、预算与白名单

请求用 API 密钥鉴权。密钥上可以设置：

- 模型白名单，限制调用方能使用哪些模型名；
- MCP 白名单，限制调用方能访问哪些 MCP 服务器；
- 预算，按日、周、月（UTC 窗口）或生命周期计算的美元上限；
- 速率限制，每分钟请求数；
- 过期时间。

用户账户有角色、可选的模型白名单，以及覆盖其全部密钥的账户预算。一个请求最终能使用
哪些模型，取密钥白名单和用户白名单的交集。

## 一个请求会经历什么

1. 鉴权：校验 API 密钥（SHA-256 摘要），检查锁定、限流桶和预算。
2. 授权：虚拟模型解析完成后，用白名单校验模型是否可用。
3. 解析：具体模型名直接使用；`auto`、`fast`、`best` 交给分类器。
4. 构建：按目标提供商渲染请求。网络搜索工具可能在这一步被拦截；未知或不支持的字段
   按[请求策略](/zh/admin/settings#request-policy)处理。
5. 调用：执行重试、回退、熔断判断、保活心跳和流式翻译。
6. 记录：写日志、用量和指标，按需导出追踪。响应翻译回客户端协议，并还原成客户端
   请求的模型名。
