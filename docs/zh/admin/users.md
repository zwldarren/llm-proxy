# 用户与角色

LLM Proxy 是多租户的：每个人都有自己的账户、自己的 API 密钥、自己的日志，还可以单独设置模型白名单和消费上限。

账户的创建和管理都在 **团队** 页面（仅管理员可见）。

## 角色

| | `admin` | `viewer` |
| --- | --- | --- |
| 使用统计与日志 | 所有用户 | 只能看自己的使用统计和日志 |
| 审计日志 | 查看并校验完整性 | 无权限 |
| 提供商 / 模型管理 / MCP 服务器 / 团队 / 服务器设置 | 完全权限 | 无权限（403） |
| API 密钥 | 自己的密钥；可设置 MCP 白名单和单密钥速率限制 | 自己的密钥；可设置 MCP 白名单；不能设单密钥速率限制 |
| 账户速率限制 | 在团队里为任意成员设置上限 | 只读（对每个密钥都生效） |
| 游乐场 | 可用 | 可用 |

在 **团队** 里修改成员角色即可升权。角色一变，该成员的所有活跃会话都会失效，需要重新登录。

## 邀请成员

**团队 → 邀请成员** 会为某个邮箱生成一条单次使用、7 天有效的链接。链接只显示一次，可以复制；配置了 SMTP 时代理会自动发送。重新发送会轮换令牌，并让上一条链接失效。

受邀者打开链接，设置用户名和密码后即登录。邀请人设定的角色、模型白名单和账户预算在接受邀请时一并生效。全程不会传输任何由管理员指定的临时密码。

成员表格上方的邀请区域保留所有邀请，而不只是未处理的：待处理的邀请可以 **重新发送** 和 **撤销**，已接受、已撤销、已过期的邀请会移入 **历史邀请**，并附带决定其状态的时间戳。

没配 SMTP 时，可复制的链接就是投递方式：谁拿到链接谁就能注册，所以只发给受邀者本人。配置了 SMTP 时，接受邀请前会先验证邮箱地址。OAuth 邀请遵循同样的规则，只有提供商返回的已验证邮箱与邀请一致时才会创建账户。

已有用户可以在 **账户 → 邮箱** 里添加或更换登录邮箱。代理会发送一条 24 小时有效的验证链接，只有收件人能完成这次更换。链接是一次性的，且与发送时账户上的地址绑定：地址一旦变化链接就失效（也无法重放旧链接来复活被替换的地址）。没有 SMTP 时，管理员可以在 **团队** 里直接设置邮箱，该地址会被标记为管理员认证。

OAuth 邀请会要求受邀者在创建第一个控制台会话前先选一个用户名，账户不会悄悄用邮箱前缀命名。

## 手动创建成员

**团队 → 添加成员**：

| 字段 | 说明 |
| --- | --- |
| **用户名** | 最多 64 个字符；可用字母、数字、`_` 和 `-` |
| **密码** | 8–72 个字符，需包含大写字母、小写字母、数字和特殊字符 |
| **角色** | `viewer`（默认）或 `admin` |
| **允许的模型** | 不选表示所有模型；明确清空表示全部拒绝 |

新成员（以及被管理员重置过密码的成员）首次登录时必须修改密码。在此之前，除个人资料、密码和登出之外的接口都会返回 `403 password_change_required`，控制台会把他们引导到 **设置新密码** 页面。

::: warning 白名单为空等于没有权限
清空模型选项并不等于「不限制」——它会把所有模型都拒掉。只有当你想让该成员完全无法使用模型时，才点 **清空选择**。
:::

修改密码会提升账户的令牌版本，使此前签发的所有 JWT 失效，并停用该用户的所有会话 API 密钥，用户必须重新登录。

### 忘记密码

登录页上的 **忘记密码？** 会向账户的**已验证**邮箱发送一条一次性链接，有效期 30 分钟。在那里设置新密码会结束该账户的所有现有会话，旧密码随即在所有地方失效。

只有当实例真的能发信时（启用了 SMTP，并在 **实例登录** 里设置了公开 base URL），这一项才是可点的链接。否则它显示为「请联系管理员」，此时恢复途径是 **团队** 里的成员密码重置（见 [成员生命周期](#member-lifecycle)）。没有密码的账户（只有通行密钥或只有 OIDC）、没有邮箱的账户，以及未验证（管理员认证）的地址，都不会走邮件重置：它们靠通行密钥、TOTP 恢复码或管理员重置恢复。该接口对所有地址的响应都相同，所以无法用它探测哪些账户存在。

## 通行密钥与双因素认证

密码、通行密钥和 TOTP 都在 **账户** 的 **登录与安全** 标签里管理。管理员账户创建完成后的首次设置就会落到这个页面（并提示添加通行密钥），所以第一个会话结束时不会只剩密码这一条路。

- 密码是可选的。无密码账户（只用通行密钥或 OIDC）可以在同一页面设置密码；此时代理要求重新认证一次，而不是输入当前密码。

- 通行密钥是一等登录方式。控制台支持可发现凭据（无需输入用户名）、每个用户多个具名通行密钥，以及同步通行密钥。必须进行用户验证（生物识别或 PIN）。通行密钥可以就地重命名，因为名字是区分笔记本和手机的唯一依据。无密码账户不能删除最后一个通行密钥，除非它同时有密码或已关联 OAuth 提供商；如果最后一个可用因素丢失，只能由管理员重置。
- 双因素认证由每个用户自行决定是否开启。启用时页面会显示供验证器 App 扫描的二维码，并附上设置密钥和 `otpauth://` URI 作为手动输入的后备方案。启用后，用密码或 OIDC 登录会追加一步验证码；通行密钥不会，因为断言本身已经同时证明了设备和持机人，单次登录即满足双因素认证，通行密钥登录仍然是单步完成。十组一次性恢复码只显示一次，提供复制和下载按钮；在你确认已保存之前，面板会持续提醒这是唯一一次显示机会。
- 如果实例必须让每一种登录方式之后都输入验证码（包括通行密钥），可以在 **实例登录** 里开启 **passkey 登录后仍要求验证码**。该选项默认关闭，因为这一步只增加操作、并不增加新的因素。
- 管理员可以在 **实例登录** 里要求所有管理员使用 TOTP。尚未启用的管理员会被跳转到 **账户 → 登录与安全**，在完成前无法使用控制台的其他部分，面板会说明原因。同一条策略也会让这些管理员无法「关闭 2FA」。
- 修改密码、通行密钥、2FA 状态或关联提供商，都要求最近重新认证过（15 分钟的 step-up 窗口）。
- 管理员可以在 **团队** 里重置成员的 TOTP/恢复码，或吊销其全部通行密钥。如果该成员既没有密码也没有关联 OIDC 提供商，吊销会被拒绝并返回 `last_factor`，因为那会把他们锁在门外。

通行密钥和 OIDC 需要一个规范的 HTTPS `public_base_url`。纯 HTTP 或用局域网 IP 部署时，仍然可以使用邀请和 TOTP；在配置好 TLS 和主机名之前，通行密钥/OAuth 接口会返回 `passkey_unavailable` / `oauth_unavailable`，而且当浏览器不支持 WebAuthn 或页面不是安全上下文时，登录页会干脆不显示通行密钥按钮。
修改公开 URL 会让已注册的通行密钥失效，因为 WebAuthn 的依赖方 ID 变了。

在 **实例登录** 里配置 OIDC 提供商时，页面会显示需要在身份提供商处登记的准确回调 URL（`<public_base_url>/api/auth/oauth/<provider id>/callback`）。提供商 ID 保存后不可更改，因此只要公开 base URL 不变，这个 URL 就一直是稳定的。

## 模型白名单 {#model-allowlists}

每个成员可以限制为只能使用一组模型名。

- 作用于模型页面（viewer 看到的是只读目录）、`/v1/models`，以及每一次推理请求。
- viewer 的 API 密钥只能在此基础上进一步收窄：创建或更新密钥时会强制取交集。
- 账户层面为 `null` 或空选择表示不限制；`[]` 表示全部拒绝。

## 账户预算 {#account-budgets}

除了单密钥预算（见 [API 密钥](/zh/admin/api-keys#budgets)），管理员还可以为成员设置**账户预算**，用它限制该成员*所有*密钥在同一 UTC 日历窗口内的合并花费。

- 超出账户预算的请求返回 **429**，错误码 `user_budget_exceeded`。
- 只有管理员能重置：**团队 → 成员 → 重置预算**。
- 成员可以在 `GET /api/me/budget` 查看自己的状态。

## 账户速率限制 {#account-rate-limits}

单密钥限流归密钥所有者管理，且只有管理员能改，因此管理员无法替成员给某个密钥单独设限。要按成员统一限制，请用**账户速率限制**，在 **团队 → 成员 → 管理速率限制** 里设置（或调用 `PUT /api/team/members/{id}/rate-limit`）。

- 它是跨该成员**所有**密钥（包括 UI 会话密钥）的 60 秒滑动窗口；`null` 表示不限制。
- 它与任何单密钥限制独立生效：任一上限触发都会返回 **429**，错误码 `rate_limit_exceeded`。
- 密钥级别的限制仍然可以在 **API 密钥** 页给管理员自己的密钥设置。

## 成员生命周期 {#member-lifecycle}

| 操作 | 效果 |
| --- | --- |
| **修改用户名 / 密码** | 用户名立即生效；重置密码会强制下次登录时修改，并吊销会话 |
| **修改角色** | 吊销会话，提升令牌版本 |
| **停用** | 将成员登出并停用其密钥；密钥和用量历史保留 |
| **重新启用** | 恢复登录和密钥使用 |
| **删除** | 吊销活跃会话，永久删除该成员**及其 API 密钥**；用量历史保留 |

代理强制执行以下安全规则：

- 不能删除、停用或降级自己。
- 不能删除、降级或停用**最后一个活跃管理员**。
- 停用或删除对成员本人来说不可逆：控制台会要求确认，如果该成员是管理员，确认提示会更严格。

## 登录保护

- `POST /api/auth/login` 按 IP 限速（默认每分钟 5 次）。
- 账户锁定**默认关闭**。开启后失败登录按**用户名**计数：5 次失败后账户锁定 15 分钟，换源 IP 也绕不过去。之所以默认关闭，是因为硬性的账户级锁定本身就是一种拒绝服务手段：知道用户名的人就能把账户锁死。上面的按 IP 限制和认证失败延迟在两种情况下都生效。
- 不存在的用户名同样要付出密码哈希计算开销，所以无法通过响应时间判断账户是否存在。
- 登录成功会清零失败计数，并记入审计日志。

这两个阈值都可以在 [服务器设置](/zh/admin/settings#security-rate-limiting) 中调整。

## 自助账户接口

账户工作区分为三个标签：**个人资料**（身份、预算、当前会话）、**偏好设置**（主题和语言，保存在当前浏览器，以及你自己的追踪后端）和 **登录与安全**。

任何已登录用户都可以：

| 接口 | 用途 |
| --- | --- |
| `GET /api/me/profile` | 个人资料和角色 |
| `GET /api/me/budget` | 账户预算状态 |
| `PUT /api/me/password` | 修改自己的密码 |
| `PUT /api/me/username` | 修改自己的用户名（需要当前密码） |
| `GET /api/me/2fa` | 2FA 状态和剩余恢复码数量 |
| `POST /api/me/2fa/begin` / `confirm` / `disable` | 启用或移除 TOTP |
| `POST /api/me/email` | 向新的登录邮箱发送验证链接 |
| `GET /api/me/passkeys` | 列出已注册的通行密钥 |
| `POST /api/me/passkeys/register/begin` / `finish` | 注册通行密钥 |
| `PATCH/DELETE /api/me/passkeys/{id}` | 重命名或删除通行密钥 |
| `GET /api/me/oauth/identities` | 列出已关联的 OIDC 身份 |
| `DELETE /api/me/oauth/identities/{id}` | 解除提供商身份关联 |
| `POST /api/me/oauth/link/complete` | 完成提供商身份关联（回调只负责验证，绑定需要已登录的会话） |
| `POST /api/me/2fa/recovery-codes` | 重新生成 2FA 恢复码 |
| `POST /api/auth/email/verify` | 完成邮箱验证链接 |
| `GET/PUT /api/me/tracing/` | 个人追踪后端配置 |
| `POST /api/me/feedback` | 为某次请求的智能路由决策打分 |
| `POST /api/auth/logout` | 退出当前浏览器（只吊销本令牌的 `sid` 所指的控制台会话；不带 `sid` 的旧版令牌 会退回为吊销该账户的全部会话） |
