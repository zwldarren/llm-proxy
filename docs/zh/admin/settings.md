# 服务器设置

**设置** 页面管的是提供商、模型、密钥和用户之外的一切：日志、功能开关、韧性策略和安全策略。这里的每一项都会写入数据库，并在修改后重新加载，不需要重启。

热加载覆盖所有工作进程，而不只是处理这次请求的那一个。其他进程会在下一次请求时（最多每秒检查一次）读到共享版本号并重新应用设置，包括那些不在配置行里的状态：网络搜索拦截器、熔断器阈值、MCP 服务器进程和个人追踪注册表。

API 密钥和团队角色的修改也以同样方式传播：被吊销的密钥或降级的角色大约一秒内就会在所有工作进程上生效，而不用等进程内缓存过期。这需要 Redis（`REDIS_ENABLED=true`），随附的 compose 已默认开启。没有 Redis 时，多工作进程部署只会热加载处理该变更的那个进程；提供商/模型查询缓存是另一个独立的可选开关（`REDIS_CACHE_ENABLED`）。

页面分 **常规** 和 **高级** 两个标签页，且仅管理员可用：这里每个设置都是实例级的。主题、语言和个人追踪属于个人设置，位于 **账户 → 偏好设置**。标签旁的 **章节** 菜单可以跳到某个分区，并显示你当前正在看的分区，不打开菜单也能知道自己在哪。

## 常规标签

### 日志管理 {#log-management}

控制台把这些控件分为 **采集**、**保留与清理** 和 **审计** 三组，便于分别检查正文采集、生命周期策略和审计覆盖项。这些分组只是展示方式，不会改变底层设置的热加载行为。

| 字段 | 默认值 | 效果 |
| --- | --- | --- |
| **记录输入/输出** | 关 | 持久化请求/响应正文的总开关。关闭时日志行照常写入（状态、Token、费用、路由、审计元数据），但所有内容载荷都存为 `{"_bodies_disabled": true}`——包括请求/响应正文、上游错误正文与消息，以及 MCP/网络搜索的参数和结果。开启后才存储正文，并受 **日志正文大小上限** 限制、按 **请求体采样率** 过滤。该开关优先于 `x-log-full: true`：无法为单个请求重新启用正文记录 |
| **记录原始流** | 关 | 保存流式响应的原始 SSE 文本。关闭时，流式响应会被重组为与非流式调用相同的 JSON——更小、像其他正文一样脱敏，查看时也无需解析 SSE。原生透传档位同样会被重组（Chat Completions、Anthropic 和 Responses 帧各自重建为非流式形态）；通用图像流保留原始帧，因为它们没有可重建的非流式形态。想检查确切的协议帧时，打开它（或对单个请求发送 `x-log-full: true`） |
| **日志保留期** | `30` | 超过天数的行会按日志类型各跑一次每日清理，分批删除（循环执行直到删完）而不是一次无界删除；`0` 表示永久保留。用量记录（仪表盘背后的数字）共用这个窗口。使用按月或总额预算时请保持 ≥ 31 天：预算校验会从 `usage_records` 汇总整个日历预算窗口内的花费（按月预算最多回看 31 天），窗口太短会悄悄少算花费，预算也就不再可靠生效。没有按月/总额预算时，更短的值没问题 |
| **审计日志保留天数** | 继承 | 审计行的独立保留期 |
| **请求体采样率** | `1.0` | **记录输入/输出** 打开后，存储正文的请求比例。采样只控制**正文采集**——元数据始终记录，被采样排除的正文存为 `{"_sampled_out": true}`（与已禁用标记不同）。客户端可以用 `x-log-full: true` 为单个请求强制完整采集 |
| **日志正文大小上限** | `1048576`（1 MiB） | 存储的请求/响应正文上限。超出上限的正文存为 `{"_truncated": true, "size": N}`（N 为原始序列化字节数），而不是载荷本身。在写入时检查，所以对用 `x-log-full: true` 强制采集的请求同样有效。`0` = 不限制 |
| **审计采样率** | 继承 | 同上，作用于审计行 |
| **脱敏敏感数据** | 开 | 存储前对请求头/正文中的凭据做掩码 |
| **额外敏感字段** | 空 | 在内置列表（`authorization`、`api_key`、`password`、`token`、`access_token`、`refresh_token`、`jwt_secret` 等）之外，额外需要脱敏的字段名，逗号分隔 |
| **手动清理** | — | **清理日志** 操作会永久删除超过所选天数的行。不可恢复 |

用量记录（仪表盘背后的数字）单独存储，但按与日志相同的窗口清理；把 **日志保留期** 设为 `0` 可让两者都永久保留。

### 网络搜索

| 字段 | 说明 |
| --- | --- |
| **启用** | 默认关闭。开启后，代理会拦截那些自身不支持原生搜索的提供商的 `web_search` 工具调用 |
| **提供商** | `searxng` 或 `ollama` |
| **SearXNG** | `url`（必填）、可选的 `api_key` 或 basic-auth 用户名/密码、`engines` 列表、`timeout`（默认 30 秒）、`max_results`（默认 10，最大 10） |
| **Ollama** | `api_key`（必填）、`base_url`（默认 `https://ollama.com`）、`timeout`、`max_results`（最大 10） |

搜索凭据在 API 里是只写的：配置了 `ENCRYPTION_KEY` 时会在磁盘上加密，读取时返回 `****`。提交掩码或留空会保留已存的密钥；要删除密钥，请清空整个提供商配置块。看起来像掩码但不完全等于 `****` 的值会返回 `422`，而不是悄悄替换已存凭据。轮换时请清空字段并输入完整的新密钥。

细节和客户端可见行为见 [工具、推理与网络搜索](/zh/api/tools#web-search)。

## 高级标签（仅管理员）

### 请求策略 {#request-policy}

代理如何处理它不认识的字段和内容块。这是全局设置，但**提供商默认**会把决定权交给各提供商的适配器（多数会丢弃未知字段；vLLM/SGLang 会透传，从而保留 `top_k`/`guided_json`/`chat_template_kwargs` 这类引擎专有参数）。选定具体值后会覆盖所有提供商自己的默认行为。

| 字段 | 选项 | 默认值 |
| --- | --- | --- |
| **未知字段处理策略** | `provider default` · `ignore` · `passthrough` · `error` | **提供商默认**——由各适配器决定（通常是 `ignore`） |
| **不支持块策略** | `provider default` · `drop` · `degrade` · `error` | **提供商默认**——由各适配器决定（目前是 `drop`） |

未知字段策略作用于内部模型不认识的**顶层**请求字段；消息内部嵌套的未知字段由各序列化器处理。走原生透传档位的请求（在支持该档位的提供商上使用 Anthropic 和 Responses 客户端）会绕过该策略，正文原样转发。

对内容块而言，先做无损转换：提供商能够表示（转换之后）的块完全不受策略影响。策略只管那些无法表示的剩余块——`drop` 删除它们，`degrade` 保留文本占位符（`[Image: …]`），`error` 拒绝请求。`degrade` 绝不会悄悄退化成丢弃：没有专属占位符的块会得到通用的 `[<TypeName> block]`。

### 智能路由

| 字段 | 默认值 | 效果 |
| --- | --- | --- |
| **启用** | 关 | 启用虚拟模型 `auto`、`fast`、`best` |
| **模式权重** | `fast 0.35`、`auto 0.65`、`best 1.0` | 各虚拟模型在质量与成本之间的偏重 |
| **路由判定器** | 关 | 在含糊的首轮请求上咨询 System One 模型；见 [路由判定器](/zh/api/routing#routing-judge) |
| **路由诊断** | 关 | 把完整路由决策载荷写入智能路由日志元数据（诊断用） |
| **优雅降级** | 关 | 当路由无法满足某项偏好（模式分配、上下文窗口的输出部分）时，降级服务而不是直接拒绝；见 [虚拟模型与路由](/zh/api/routing) |

信号集在进程内运行（元数据 + 结构信号；嵌入信号已随支撑它的重型 ML 栈一并移除）。可选的判定器是智能路由里唯一会额外发起上游调用的部分——每个被判定的轮次一次简短的 System One 请求，受其门限和截止时间约束，判定结果及其费用记录在该请求的路由元数据中。每次这类调用在**日志 → 判定调用**里也是独立一行（日志类型 `judge`），归属于触发它的请求；花费和预算汇总统计的正是这一行。可以在日志详情页提交针对该请求的反馈。

见 [虚拟模型与路由](/zh/api/routing)。

### 提供商选择 {#provider-selection}

当多个同优先级的提供商都能服务同一个模型时，按以下策略排序：

| 策略 | 行为 |
| --- | --- |
| `session_sticky`（默认） | 让同一对话固定在一个提供商上，保持其提示词缓存命中。配置了 Redis 时由 Redis 记住选择，否则用基于对话键的确定性 rendezvous 哈希固定。没有对话键的请求退化为随机选择 |
| `random` | 在优先级组内随机选择——负载分摊均匀，但同一对话每轮可能落到不同提供商，提示词缓存需要重新预热 |
| `cost_optimized` | 最便宜且可用的提供商优先。只有当同优先级的映射价格不同时，它才与 `random` 有区别 |
| `balanced` | 在成本与实测延迟之间权衡，并保留少量探索比例，避免某个提供商的样本过时 |

无论采用哪种策略，高优先级组总是先于低优先级组尝试。

会话粘性优先看客户端自己的会话请求头（`x-opencode-session`、`x-claude-code-session-id`、Codex 的 `x-codex-turn-metadata`、Pi 的 `x-session-affinity` 等），其次是请求体里显式的会话 id，然后是可信代理传来的 `x-session-id`，最后是首条用户消息的哈希。这与 [OpenCode 线路](/zh/admin/providers) 转给上游的对话句柄是同一个键，所以两层对「对话属于谁」的判断一致。Redis 会记住这个对应关系 30 分钟；如果对话实际由漂移后的提供商（回退）在服务，而不是按哈希选中的那个，就在服务期间持续续期。

### 重试与回退 {#retry-fallback}

| 字段 | 默认值 | 效果 |
| --- | --- | --- |
| **最大重试次数** | `3` | 对同一提供商的重试次数（可在模型上按模型覆盖） |
| **最大回退次数** | `10` | 单个请求最多切换多少次提供商 |

### 熔断器

| 字段 | 默认值 | 效果 |
| --- | --- | --- |
| **启用** | 开 | 跳过正在故障的提供商 |
| **失败阈值** | `5` | 连续失败多少次后熔断该提供商 |
| **冷却时间** | `60` 秒 | 多久之后重新尝试该提供商 |

该标签会列出每个提供商的实时熔断状态，并提供 **全部重置** 和按提供商重置。计数器只在进程内，重启即清零。

### 实例登录

| 字段 | 默认值 | 效果 |
| --- | --- | --- |
| 公开 base URL | 空 | 规范的对外 URL（`https://proxy.example.com`）。WebAuthn 的 RP ID 和 OAuth 重定向 URI 都由它推导。必须是 HTTPS，开发时可用 `http://localhost`。修改它会让已注册的通行密钥失效 |
| 要求管理员使用 2FA | 关 | 阻止尚未确认 TOTP 的管理员，控制台会把他们引导到 **账户 → 登录与安全** |
| 启用 SMTP | 关 | 发送邀请、邮箱验证和密码重置邮件。未启用时，邀请以可复制链接的形式给出，忘记密码只能找管理员 |
| SMTP 主机 / 端口 / 用户名 / 密码 / 发件地址 | 空 / `587` / 空 / 空 / 空 | 标准 SMTP 投递。密码在磁盘上加密，API 响应里做掩码 |
| STARTTLS / TLS（SMTPS） | 开 / 关 | SMTP 连接的传输安全 |
| OIDC 提供商 | 空 | 具名 OpenID Connect 提供商（`id`、显示名称、issuer、client ID/secret、scopes）。只有已启用的提供商才会出现 OAuth 按钮。密钥在磁盘上加密，读取时做掩码 |

SMTP 细节在启用投递后才会出现，已保存的 OIDC 提供商默认折叠。表单在保存前会校验 URL、必填字段和 SMTP 端口；**放弃更改** 会恢复为上次保存的快照，带着未保存的修改离开则需要确认。

SMTP 密码和 OIDC client secret 都是只写的：读取时返回 `****`。原样提交这个掩码或留空会保留已存的密钥。就地修改掩码会被拒绝，而不会覆盖真实凭据；轮换时请清空字段并输入完整的新密钥。

OIDC 提供商的 **id** 保存后永久不变：已存的 client secret 以它为键，所以对于已有提供商，控制台会锁定该字段。每个 **issuer** 必须是 HTTPS URL（开发时可用 `http://localhost`）；代理拒绝保存纯 HTTP 的 issuer，因为 client secret 和授权码都要发给它。

没有配置 HTTPS 公开 base URL 时，通行密钥和 OAuth 接口不可用。这是有意为之：WebAuthn 在纯 HTTP 或局域网 IP 上无法做到安全。

### 安全与速率限制 {#security-rate-limiting}

| 字段 | 默认值 | 效果 |
| --- | --- | --- |
| 启用登录锁定 | 关 | 反复登录失败后锁定账户（按用户名计数）。默认关闭，因为硬性的账户级锁定意味着知道用户名的人就能故意把账户锁死 |
| 启用 API 密钥 IP 锁定 | 关 | 反复 API 密钥认证失败后锁定客户端 IP。默认关闭——锁定按 IP 计数，一个凭据错误的客户端会把共用该地址的所有人都锁在外面（NAT、企业出口，或所有都表现为 `127.0.0.1` 的本地测试请求）。面向不可信网络的实例建议开启 |
| 最大登录失败次数 / 锁定时长 | `5` / `900` 秒 | 仅在启用登录锁定时使用 |
| 最大 API 密钥失败次数 / 锁定时长 | `10` / `300` 秒 | 仅在启用 API 密钥 IP 锁定时使用 |
| 认证失败延迟 | `100` 毫秒 | 认证失败时的人为延迟（±10% 抖动） |
| 关闭速率限制 | 关 | 限流总开关：关闭限流桶、单密钥每分钟请求数、两种失败锁定以及认证失败延迟。预算上限和正文大小限制不受影响。开启时界面会醒目告警——代理将暴露于暴力破解/DoS |
| Redis 失败关闭 | 开 | 使用 Redis 限流时，Redis 出错就拒绝请求（而不是放行） |
| 启用 HSTS / max-age | 开 / `31536000` | `Strict-Transport-Security` 头。只有本地 HTTP 开发时才应关闭 |
| 最大请求体大小 | `67108864`（64 MiB） | `0` 表示不限制。声明的 `Content-Length` 会预先检查；分块或未声明长度的正文在流式读取时计量，超出限制才拒绝 |

锁定计数器保存在进程内，重启即清空。除非启用了 Redis 限流，限流窗口也都在内存里。

### 速率限制 {#rate-limits}

内置 IP 限制的按桶覆盖值，格式为 `N/period`（`5/minute`、`100/hour`）。可编辑的桶及其默认值：

| 桶 | 默认值 |
| --- | --- |
| `auth.login` | `5/minute` |
| `auth.setup` | `5/minute` |
| `auth.setup_status` | `10/minute` |
| `auth.capabilities` | `20/minute` |
| `auth.mfa` | `10/minute` |
| `auth.step_up` | `10/minute` |
| `auth.invite_accept` | `10/minute` |
| `auth.invite_status` | `20/minute` |
| `auth.passkey` | `20/minute` |
| `auth.oauth` | `20/minute` |
| `auth.email_verify` | `20/minute` |
| `auth.password_reset` | `5/minute` |
| `auth.password_reset_confirm` | `10/minute` |
| `account.sensitive` | `10/minute` |

未知的桶名或无法解析的值会返回 422；计数必须为正数（`0/minute` 会被拒绝，而不是悄悄禁用该桶）。按 API 密钥的限制（`rate_limit_rpm`）在密钥本身上设置。
