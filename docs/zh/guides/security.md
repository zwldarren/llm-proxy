# 安全加固

LLM Proxy 夹在你的应用和付费上游 API 之间，保存提供商凭据，并提供管理控制台。把
代理暴露到公网之前，请对照这一页逐项检查。

## 凭据模型一览

| 凭据 | 存储方式 | 说明 |
| --- | --- | --- |
| API 密钥（`sk-…`） | bcrypt 哈希 | 明文只显示一次；仅用于 `/v1/*` 和 `/servers/*` |
| 控制台会话 | HS256 JWT，24 小时，不可刷新，存放在 `HttpOnly` 的 `/api` cookie 中 | 仅用于 `/api/*`；密码/角色/停用状态变化即失效；不安全的 cookie 调用需要 `X-CSRF-Token` 双提交头 |
| 游乐场会话密钥 | `HttpOnly` 的 `/v1` cookie，24 小时 | 控制台专用的浏览器传输方式；显式的 `Authorization`/`x-api-key` 头优先级更高 |
| 用户密码 | bcrypt，策略 8–72 字符且需混合字符类别 | 管理员创建的账户强制改密 |
| 提供商 API 密钥 | 静态加密（Fernet，`enc:` 前缀） | 查看仅管理员可用且会记入审计；轮换 `ENCRYPTION_KEY` 会导致其无法解密 |
| JWT / 加密密钥 | 自动生成，存于数据库 | 保管好数据库；备份中包含这两者 |

## 边界与传输

| 项目 | 默认值 | 建议 |
| --- | --- | --- |
| TLS | 在你的反向代理处终止 | 生产环境始终使用 HTTPS；见[反向代理与 TLS](/zh/deployment/reverse-proxy) |
| HSTS | **开启**，`max-age=31536000; includeSubDomains` | 保持开启；只在本地 HTTP 开发时关闭 |
| 安全响应头 | `nosniff`、`DENY`、`Referrer-Policy`、`Permissions-Policy`，CSP `default-src 'self'`（script/style 允许 `unsafe-inline`） | 由应用发出，边缘层无需重复设置 |
| `TRUSTED_PROXIES` | RFC1918 + 回环 + 链路本地 | 换成你实际的代理网段——它是**替换**而不是追加。来自非受信对端的伪造 `X-Forwarded-For` 按设计会被忽略 |
| 请求体上限 | 64 MiB，流式传输中即生效（分块计时，不提前拒绝） | 与反向代理自身的上限保持一致 |
| CORS | 关闭（来源列表为空） | 只添加确实需要浏览器访问的来源 |

## 滥用防护

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 速率限制 | 开启（内存） | `rate_limit_disabled` 是总限流开关：速率限制桶、按密钥的每分钟请求数、两种失败锁定以及认证失败延迟都受它控制。它**不会**解除预算上限或请求大小限制。开启时界面会显著警告 |
| 共享速率限制 | 直到 `REDIS_RATE_LIMIT_ENABLED=true` 才启用 | 多工作进程/多副本部署必须启用：内存后端**每个进程**一个窗口，N 个工作进程就会执行 N 倍于配置值的限制。`GET /api/health` → `services.rate_limiting.backend` 显示当前使用哪个存储 |
| Redis 故障模式 | `redis_rate_limit_fail_closed=true` | Redis 出错时拦截请求——对公网部署更安全 |
| 登录锁定 | **默认关闭。** 启用后：15 分钟内 5 次失败，按用户名计数 | 默认关闭是因为硬性按账户锁定会让任何知道用户名的人把账户锁死。按 IP 的 `auth.login` 限制和认证失败延迟始终生效 |
| API 密钥 IP 锁定 | **默认关闭。** 启用后：5 分钟内 10 次失败，按**客户端 IP** 计数 | 默认关闭是因为锁定按 IP 计数：一个用错凭据的客户端会把共用该地址的所有人一起锁在外面（NAT、企业出口——开发环境下每个请求都是 `127.0.0.1`）。可从不可信网络访问的实例建议开启。作用于 `/v1/*` 和 `/servers/*`；认证失败延迟始终生效 |
| 模型白名单拒绝 | 403，不计为认证失败 | 该密钥已经通过认证，所以请求被禁的模型既不触发 IP 锁定，也不承担失败延迟 |
| WebSocket 配额 | 每个可计费回合前做预算检查 | `/v1/responses` 在每次 `response.create` 前重新执行密钥校验；`/v1/realtime` 在转发每次 `response.create` 前检查，回合结束后再检查一次。执行是尽力而为：花费会缓存 15 秒，用量行异步写入，因此突发流量或进行中的回合可能超出上限 |
| 认证失败延迟 | 100 ms ±10% 抖动 | 拖慢暴力破解；公网实例保持开启 |
| 控制台认证桶 | `auth.login` 5/分钟，`auth.setup` 5/分钟（流量最高的两个桶） | 可按桶调整；完整列表见[服务器服务器设置 → 速率限制](/zh/admin/settings#rate-limits) |

## 密钥、角色与租户

- 最小权限：`viewer` 账户完全无法访问提供商/模型/团队/MCP/设置相关 API。`admin`
  只留给运维人员。
- 密钥卫生：每个生产密钥都设置过期时间、`rate_limit_rpm`、模型白名单和预算。
  记住，显式空白的白名单会拒绝一切。
- 账户预算限制某个成员所有密钥的总额，且只能由管理员重置。
- 隔离保证：viewer 只能看到自己的日志/用量；API 密钥按所有者隔离，管理员也
  不例外；存储的 Responses 按密钥划分命名空间，租户之间无法读取或删除对方的记录。
- 个人追踪：非管理员的 `base_url` 必须是公网主机；内部收集器需要列在
  `HTTP_ALLOWED_HOSTS` 中。管理员保留自建环境的宽松检查。把管理员降级为 viewer 会
  清空其个人追踪配置，之后可以重新添加公网收集器。

## 外发媒体下载 {#outbound-media-downloads}

客户端提供的图像 URL 会在两处触网：一是聊天消息的 `image_url`，由会主动抓取的
提供商处理（Ollama 会把它下载成 base64）；二是 Decisions 请求的 `input_image`，当它
被桥接到 System One 上游时（这些上游都不抓取远程图像，由代理代劳）。两处走同一套
经 SSRF 校验的抓取流程：

- 回环地址、RFC1918、链路本地、CGNAT、组播、云元数据主机，以及携带凭据的 URL，
  一律直接拒绝。
- 主机名会先解析，返回的每个地址都会检查，所以指向私有 IP 的公网名称同样会被拒绝。
- 重定向会被跟随（最多五次），且**每一跳都按第一跳的规则校验**：http→https 升级
  或 CDN 的签名跳转照常可用，重定向到 `127.0.0.1` 或解析到那里的名称则不行。
- 响应体按流读取，并限制在 `HTTP_MAX_DOWNLOAD_BYTES`（默认 20 MiB），因此指向几 GB
  文件的 URL 只会浪费一个被拒绝的请求，而不是工作进程的内存。20 MiB 是主流视觉 API
  单图的上限，所以这个上限不会切断任何一个上游愿意接收的图像。
- 单个请求的下载还作为一组受限：最多同时四个，内联负载合计不超过
  `HTTP_MAX_REQUEST_DOWNLOAD_BYTES`（默认 64 MiB，与代理接受的请求体大小相同）。因此
  一个列举了大量 URL 的请求无法让代理占用几百 MB；内存峰值就是这个总量加上正在下载
  的部分。
- 在桥接的 Decisions 路径上，下载被拒绝或失败会返回 `400` 并指明该 URL：否则请求就
  会基于模型从未见过的证据给出回答。聊天媒体则按 ADR-0046 的另一条规则处理：丢弃
  该部分，请求照常进行。

这套规则可能误伤内部图像主机，以及 DNS 解析到私有网段的主机（分离解析 DNS）。把这些
主机列进 `HTTP_ALLOWED_HOSTS` 即可豁免；协议和凭据规则仍然适用。

## 外发请求 {#outbound-requests}

代理自己抓取的每个 URL（提供商的 `base_url`、个人追踪收集器、远程 MCP 服务器、
网络搜索端点、客户端的媒体 URL）在配置时都会做 SSRF 校验。通过代理共享外发会话
发出的请求还会**在建立连接时**再检查一次：默认后端的 DNS 解析器会拒绝落在禁用网段
的解析结果，因此一个在保存配置时指向公网地址、之后改指私有地址的主机名（DNS 重绑定）
也无法连上。重定向目标在两个后端中都会解析并检查。字面地址和 `localhost` 只在配置
时检查；`HTTP_ALLOWED_HOSTS` 在两处都豁免对应主机。强制
`HTTP_CLIENT_BACKEND=httpx2` 会保留配置时检查和重定向检查，但没有连接时的解析器；
MCP 服务器客户端、智能路由裁判/飞轮客户端以及 Langfuse 和 OTLP/LangSmith 导出器各有
自己的 HTTP 客户端，因此只受配置 URL 检查保护。见 ADR-0047。

代理读回的内容同样有上限：

- 缓冲式提供商响应最多读到 `HTTP_MAX_RESPONSE_BYTES`（默认 64 MiB），超过即以 `502`
  拒绝，损坏或有恶意的端点无法用超大的响应体耗尽工作进程内存。
- 流式响应的单行上限为 8 MiB。否则一个永远不发换行符的端点会让 SSE 读取缓冲区无限
  增长。
- 一次 MCP 工具调用、提示词或资源，其内容块合计上限为 8 MiB（`MCP_MAX_RESULT_BYTES`）；
  被截断的负载会带上标记，好让模型能分辨截断的回答和完整的回答。

## MCP

MCP 服务器会执行命令并访问网络，所以策略默认拒绝：

- 为每个服务器把所需的**命令**和**环境变量**精确列入白名单。参数中的 shell 元字符
  直接拒绝。
- SSRF 防护在创建或更新服务器时解析主机名并拒绝被封锁的 IP（回环、RFC1918、链路
  本地、云元数据、CGNAT）。MCP SDK 自带 HTTP 客户端，所以这项检查发生在配置时而非
  连接时。见[外发请求](#outbound-requests)。
- 保持 `require_key_mcp_permissions=true`，让每个 MCP 服务器都要按 API 密钥显式授权。
- 每个已配置的 MCP 服务器在每个工作进程上的会话槽位有上限（1000 个会话，闲置 10
  分钟），密钥持有者无法用 `initialize` 循环耗尽某个端点。
- 远程（`streamableHttp`）服务器无法设置自定义认证头：优先用 stdio，或用你自己
  掌控的网络路径。
- 每次 MCP 调用都会在 日志 → MCP 调用 中以脱敏参数记录。

见 [MCP 服务器](/zh/admin/mcp#security-policy)。

## 日志与隐私

- 正文默认关闭（`log_input_output`）：每行仍记录状态、Token、费用、路由和审计
  元数据，但所有内容负载都存为 `{"_bodies_disabled": true}`：请求/响应正文、上游
  错误正文与消息、MCP/网络搜索的参数与结果。行内的自由文本错误原因和堆栈保持保留
  （它们属于分类信息而非负载；拒绝记录依赖它们）；上游错误负载存放在
  `log_metadata.error_details` 中，会被清除。需要排查到负载级别时再有意识地开启，
  而且事后要关掉。它是总开关：`x-log-full: true` 无法为单个请求重新开启正文。
- 脱敏默认开启；在**敏感字段**中添加你自己的字段名。脱敏值保留前 3 位和后 4 位
  （≤ 8 字符 → `***`）。内置集合覆盖 `Authorization`、`x-api-key` 和
  `Cookie`/`Set-Cookie` 头中的凭据，以及正文和 MCP/工具参数。
- 采样减少正文采集（前提是正文已开启），不丢元数据；未采中的正文存为
  `{"_sampled_out": true}`（与「关闭」标记不同），排查时 `x-log-full: true` 可对单个
  请求强制完整采集。
- 保留期默认 30 天，日志、审计和用量记录一致。涉敏负载可以缩短。
- 审计链：定期从 日志 → 审计日志 → **验证完整性** 校验，并保存结果。链校验
  失败意味着审计历史被改过。
- 不存在导出端点：把数据库访问权限视为对所有日志的访问权限，并据此收紧。

## 密钥与轮换

| 操作 | 影响 | 步骤 |
| --- | --- | --- |
| 轮换 API 密钥 | 除该密钥外无影响 | 创建替代密钥、切换客户端、删除旧密钥 |
| 重置用户密码 | 撤销会话，下次登录强制改密 | 管理员：团队 → 重置密码 |
| 轮换提供商 API 密钥 | 无影响 | 编辑提供商（查看操作会记入审计） |

轮换 `JWT_SECRET` 或 `ENCRYPTION_KEY` 的影响会超出控制台，尤其是
`ENCRYPTION_KEY`，一旦轮换，已存储的提供商密钥在重新录入之前都无法解密。两者在首次
运行时自动生成，把它们从数据库读出来的托管/迁移 SQL 在
[升级与备份 → 密钥：轮换会破坏什么](/zh/deployment/upgrades#secrets-what-rotation-breaks)。

## 隔离网络或隐私要求严格的部署

- 设置 `UPDATE_CHECK__ENABLED=false`，停止版本检查访问 GitHub。
- 追踪按用户、按需开启；保持关闭即可让请求内容留在你的基础设施内。
- 网络搜索和 MCP 在显式配置之前都是关闭/默认拒绝状态。
